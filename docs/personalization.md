# 8단계 프리셋·즐겨찾기·검색 기록

구현 범위는 FNC-P-001~007이다. 기존 모델과 7단계의 서명 세션·CSRF
미들웨어를 그대로 사용한다. 모든 개인 데이터 조회·변경·삭제를 회원 ID로
제한한다. 비회원은 CSRF 검사보다 먼저 401을 받는다.

## 명세 적용과 모호한 부분

- 프리셋 조건은 FNC-S-001로 정규화하고 키워드를 제외한다. API 예시에는
  검색 조건 전체라고 되어 있지만 기능·테이블 명세의 키워드 제외 규칙을
  우선했다. 선택적 키워드 저장 옵션은 요청 형식이 없어 추가하지 않았다.
- 이름은 앞뒤 공백을 제거한 후 1~30자를 검사한다. 중복은 같은 회원 안에서
  대소문자를 구분한 정확한 이름 비교다. 목록은 이름순이다.
- 프리셋 생성 시 30개 제한을 중복 이름 검사보다 먼저 적용한다.
  수정 시에는 개수 제한 없이 이름 중복 제약을 적용한다.
- 즐겨찾기 page/size의 허용 범위가 별도로 없어 기존 검색과 같은
  page=0 이상, size=10/20/50, 기본 0/20을 사용한다. 최근 등록순이며
  같은 등록 시각이면 영상 ID순으로 고정한다. 현재 페이지의 ID만 조회한다.
- 즐겨찾기는 기존 fetch_details와 EntityCache를 사용한다. 24시간 미만은
  캐시를 재사용하고 정확히 24시간부터 갱신한다. 누락된 ID는 영상 캐시에서
  삭제하되 즐겨찾기 ID는 유지하고 available=false와 안내 제목을 반환한다.
- 쿼터 차단 시 기존 상세 조회의 캐시 대체 동작을 사용한다. 28일 미만의
  캐시가 있으면 표시하고 STALE_STATS 경고를 반환한다. 사용 가능한 정보가
  없는 실패 항목도 응답 형식에 맞춰 available=false로 반환하되, 삭제 안내
  제목을 붙이지 않고 PARTIAL_FAILURE 경고를 반환한다. ID는 삭제하지 않는다.
- 즐겨찾기의 채널 정보는 24시간 이내 기존 채널 캐시가 있을 때만 표시한다.
  채널 캐시가 없으면 관련 값은 null이다. 추가 channels.list는 호출하지 않는다.
  파생 지표는 기존 렌더러의 calc 객체와 계산값 라벨을 그대로 사용한다.
- 검색 기록은 정상 완료한 회원 검색마다 저장한다(캐시 적중·0개 결과 포함).
  정규화된 조건, 키워드, 결과 개수, 검색 시각만 저장하며 영상 목록은 없다.
  시각이 같으면 ID 역순으로 최근 50개를 결정한다. 저장 실패는 롤백하고
  검색어·SQL 매개변수 없이 경고를 남기며 완성된 검색 응답을 반환한다.
- 즐겨찾기 해제는 현재 회원의 ID만 삭제하는 멱등 연산이다. 다른 회원의
  같은 영상 ID에는 영향이 없으며 없는 즐겨찾기 해제도 204다.
- 불러오기는 조건 JSON 반환까지만 구현했다. 화면과 개인정보처리방침 페이지는
  계획의 10단계 범위다. 개인정보는 기존 회원 탈퇴의 FK CASCADE로 즉시 삭제된다.

## 기존 파일 수정 이유

- app/main.py: 개인화 라우터 세 개를 실제 앱에 등록했다.
- app/search/service.py: 정상 검색 완료 지점과 캐시 적중 반환 지점에 회원
  기록 저장을 연결했다. 라우트에서 기존 current_user로 확인한 회원 ID를
  전달하며 비회원은 저장하지 않는다. 서비스에 app.state.clock을 전달해
  기존 세션·캐시·검색 기록이 같은 시각 기준을 사용하도록 했다.

새 패키지, 모델·마이그레이션, 세션·CSRF 구조 변경, 9단계 이후 기능은 없다.
테스트는 mock 어댑터를 사용한다.
