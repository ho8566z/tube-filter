# 7단계 회원·세션·이용 제한

구현 범위는 FNC-U-001~006, FNC-Q-007과 관련 보안 요구사항이다.
회원 API 경로·본문·응답은 `spec/08_API_명세서.md`를 따른다.
회원가입 시 개인정보처리방침 동의를 검사하며 자동 로그인하지 않는다.
정책 화면과 프리셋·즐겨찾기·검색 기록 기능은 이번 단계에 포함하지 않는다.

## 세션과 CSRF

Starlette SessionMiddleware가 itsdangerous로 서명한 `TF_SESSION` 쿠키를 사용한다.
HttpOnly, SameSite=Lax, Path=/, Max-Age=86400이며 HTTPS 요청에는 Secure를 붙인다.
서버의 `SESSION_SECRET`으로 서명을 확인하고, 각 요청에서 최종 활동 시각을
갱신한다. 마지막 요청 후 정확히 24시간 이상이면 세션을 비운다.
테스트는 `app.state.clock`을 교체해 비활동 만료와 갱신 경계를 확인한다.
쿠키는 암호화되지 않으므로 비밀번호 원문이나 해시를 넣지 않는다.
회원 식별에는 ID와 생성 시각을 함께 써서 탈퇴 후 SQLite ID 재사용을 구분한다.

화면 구현 전 CSRF 토큰을 받기 위한 최소 보조 API로
`GET /api/v1/auth/csrf` → `{"csrfToken": "…"}`를 추가했다(Cache-Control: no-store).
클라이언트는 쿠키를 유지하고 모든 POST/PUT/PATCH/DELETE 요청에
`X-CSRF-Token` 헤더를 보낸다. 비회원 검색·가입·로그인도 동일하다.
로그인 성공 시 세션과 토큰이 교체되므로 다시 GET으로 토큰을 받는다.
토큰 누락·불일치는 403 FORBIDDEN이다. 세션 없는 로그아웃만 204로 허용한다.
인증이 필요한 API는 CSRF 검사보다 먼저 비회원에게 401 UNAUTHORIZED를 반환한다.
기존 개인 데이터 경로의 권한 경계만 적용하며 해당 기능 API를 미리 구현하지 않는다.

## 비밀번호와 탈퇴

아이디는 소문자로 통일하고 4~20자 영문 시작·영문/숫자 규칙을 검사한다.
비밀번호는 영문·숫자를 포함한 8~64자이며 bcrypt로 저장·비교한다.
명세는 다국어 비밀번호의 바이트 수를 정하지 않았다. bcrypt의 72바이트 한도에
맞춰 UTF-8 72바이트를 넘는 입력은 검증 실패로 거부한다(잘라서 저장하지 않음).
일반 검증 실패 코드는 기존 공통 처리와 같은 VALIDATION_ERROR다.
아이디 없음·비밀번호 오류는 동일한 LOGIN_FAILED 응답을 사용한다.
요청 모델은 SecretStr로 비밀번호를 보호하고 검증 응답에 입력값을 포함하지 않는다.

탈퇴는 하나의 트랜잭션에서 app_user를 삭제하고 기존 ON DELETE CASCADE FK로
filter_preset, favorite_video, search_history를 즉시 삭제한다.
다른 회원의 행과 검색·영상·채널 캐시는 유지한다. 모델/마이그레이션 변경은 없다.

## 카운터 기준과 알려진 한계

- 일일 신규 검색은 날짜 기준이 명시되지 않아 KST 자정에 초기화한다.
  비회원은 IP, 회원은 계정 ID를 키로 사용하고 환경변수
  LIMIT_SEARCH_GUEST_PER_DAY(5), LIMIT_SEARCH_USER_PER_DAY(20)를 적용한다.
- 검색 파이프라인의 캐시 미적중 훅에서 확인·증가한다. 캐시 적중·견적·결과 조회는
  일일 횟수를 쓰지 않는다. 훅을 통과한 후 외부 호출이 실패해도 횟수는 복구하지 않는다.
- 분당 제한은 IP 기준 60초 슬라이딩 윈도다. /api/v1/search 및 그 하위 경로는
  LIMIT_SEARCH_PER_MIN(10), 나머지 요청은 LIMIT_OTHER_PER_MIN(60)을 적용한다.
  캐시 적중과 검증/인증 실패 요청도 분당 횟수에 포함한다.
  정확히 60초 전 요청은 윈도에서 제외하며, 제한으로 거부된 요청은 추가 집계하지 않는다.
- IP는 ASGI request.client.host를 사용한다. 앱에서 임의의 X-Forwarded-For를 신뢰하지 않는다.
- 카운터는 Lock으로 확인·증가를 보호하며 이전 날짜/비활성 IP 기록을 정리한다.
  메모리 방식이므로 재시작하면 초기화되고 여러 프로세스 간 공유되지 않는다.
  로그인 시도 전용 제한(sec-007)은 구현하지 않았다.

검증은 mock YouTube 어댑터만 사용한다. 신규 테스트는 가입·로그인·변경·탈퇴,
비회원 권한·CSRF·서명 변조·세션 갱신/만료, FK 삭제와 캐시 보존,
일일 5/20회·KST 자정·분당 10/60회·60초 경계·동시 증가·캐시 제외를 확인한다.
