| 주의사항 | 1. 이 프로젝트는 취업을 위한 포트폴리오 용도의 개인 프로젝트다.<br>2. 실무 프로세스를 따라 하되 과하게 설계하지 않는다.<br>3. 개발은 Codex가 진행하고, 이 문서(요구 명세서·기능 명세서·API 명세서 등)가 구현 기준이다.<br>4. 명세에 없는 입력 형식·API 응답 필드는 가정하지 말고, 실제 YouTube API 응답을 먼저 확인한 뒤 구현한다.<br>5. 이 문서의 일정(WBS)·수치(쿼터 상한, 캐시 시간, 이용 횟수 제한)는 작성 시점(2026-11-10)의 초안이다. 구현하면서 실제 값으로 고친다. |
| 프로젝트 목표 |  |
| 프로젝트명 | tube-filter (YouTube 영상 정밀 필터 검색 서비스) |
| 한 줄 설명 | YouTube 기본 검색이 제공하지 않는 세밀한 조건(정확한 길이, 조회수·좋아요 범위, 구독자 수 범위, 구독자 대비 조회수 %, 태그, 업로드 요일·시간대, 채널 업로드 빈도 등)으로 영상을 걸러 주는 웹 서비스. |
| 원천 데이터 | 입력: 사용자가 정한 검색어와 필터 조건.<br>출력: YouTube Data API v3(공식 API)가 돌려주는 영상·채널 공개 정보(제목, 게시일, 길이, 태그, 카테고리, 조회수, 좋아요 수, 댓글 수, 채널의 구독자 수·영상 수·개설일·국가, 채널 업로드 목록 등).<br>영상 파일·오디오는 받지 않는다(링크·공식 임베드 플레이어로만 재생). |
| 2차 가공 데이터 | 서비스가 계산한 값(YouTube가 제공한 지표가 아님, 화면에 항상 표시): 구독자 대비 조회수(%), 좋아요율(%), 댓글 참여율(%), 채널 영상당 평균 조회수, 채널 최근 30/60/90일 업로드 수, 업로드 요일·시간대(KST).<br>결과 요약 통계(평균·중앙값·최대), 구독자 대비 조회수 산점도, 업로드 요일×시간대 히트맵. |
| 최종 목적 | ‘구독자 1만 명 이하 채널의 8~15분 영상 중 최근 30일 안에 올라왔고 좋아요율이 높은 것’처럼 유튜브 기본 UI로는 만들 수 없는 조합 조건으로 영상을 찾게 한다.<br>포트폴리오 관점의 핵심: ① 외부 API 쿼터(하루 10,000 units)를 설계로 푸는 과정(비용 순서대로 필터 적용, 캐싱, 사전 견적) ② YouTube API 서비스 개발자 정책을 지키는 설계(파생 지표 표기, 캐시 30일 제한, 브랜딩, 개인정보처리방침). |
| 권한 등급 |  |
| 비회원 | 로그인하지 않은 상태. 검색·필터·결과 조회·채널 상세·쿼터 현황·정책 페이지를 볼 수 있다.<br>프리셋 저장, 즐겨찾기, 검색 기록은 쓸 수 없다. 하루 신규 검색 횟수가 회원보다 적다(설정·규약 시트). |
| 회원 | 아이디·비밀번호로 가입한 사용자. 비회원 기능에 더해 필터 프리셋 저장, 즐겨찾기(영상 ID만 저장), 검색 기록을 쓸 수 있다.<br>관리자 권한은 두지 않는다(포트폴리오 범위를 넘는 설계를 피함). 운영 정보(쿼터 사용량)는 모든 사용자에게 공개한다. |
| 서비스 구성 |  |
| 웹 앱 (FastAPI) | 하나의 서버가 화면(Jinja2 템플릿 + 바닐라 JS)과 JSON API를 함께 제공한다.<br>- 회원·프리셋·즐겨찾기·검색 기록 관리<br>- 검색 파이프라인(후보 수집 → 영상 상세 조회 → 영상 필터 → 채널 조회 → 채널 필터 → 활동 조회 → 계산·정렬)<br>- 쿼터 기록·사전 견적·상한 차단, 캐시 저장·정리 |
| YouTube 어댑터 | YouTube Data API v3 호출은 이 모듈 한 곳만 거친다(nfr-006). 호출마다 쿼터 비용을 기록하고, 테스트에서는 가짜(mock) 어댑터로 바꿔 끼운다.<br>허용된 엔드포인트: search.list, videos.list, channels.list, playlistItems.list, videoCategories.list. 그 외 호출·스크래핑·비공식 API는 금지(comp-005). |
| DB (SQLite) | 회원, 프리셋, 즐겨찾기(영상 ID), 검색 기록, 검색 결과 캐시, 영상·채널 캐시, 쿼터 사용 기록. 파일 DB 하나로 시작하고 SQLAlchemy로 접근해 MySQL 등으로 바꾸기 쉽게 둔다. |
| 화면 (브라우저) | 필터 패널 + 결과 목록이 한 화면인 검색 화면이 중심. Chart.js로 산점도·히트맵을 그린다. 영상 재생은 YouTube 공식 임베드 플레이어(iframe) 또는 유튜브 링크. |
| 기술 스택·외부 연동 사양 |  |
| 백엔드 | - 언어·프레임워크: Python 3.12, FastAPI, Uvicorn<br>- 패키지·가상환경: uv (uv sync로 .venv 동기화)<br>- DB 접근: SQLAlchemy 2.x, 마이그레이션 Alembic<br>- 외부 호출: httpx (YouTube Data API v3 REST)<br>- 비밀번호: bcrypt<br>- 검증: Pydantic v2 |
| 프론트 | - Jinja2 템플릿, 바닐라 JavaScript(fetch)<br>- 그래프: Chart.js<br>- 반응형 CSS(모바일 폭 360px 이상) |
| 테스트·품질 | - pytest (YouTube API는 mock 어댑터로 대체, 필터는 경계값 단위 테스트)<br>- ruff(린트·포맷) |
| 외부 API | - YouTube Data API v3 (공개 데이터만 사용하므로 API 키 방식, OAuth 없음)<br>- 기본 할당량 하루 10,000 units, 태평양 시간(PT) 자정에 초기화<br>- 키는 환경변수 YOUTUBE_API_KEY로만 주고 저장소에 올리지 않는다(sec-002) |
| 개발 환경 | Windows 10, VS Code 또는 PyCharm, Git/GitHub, uv, Python 3.12. 개발 담당: Codex(Claude가 문서 작성·검토). |
| 실행 흐름 (검색) |  |
| 1. 조건 입력 | 사용자가 키워드와 필터를 입력한다. 화면이 ‘예상 쿼터 비용’을 보여 준다(quota-002). 같은 조건의 6시간 이내 검색 결과가 있으면 비용 0으로 바로 보여 준다(cache-001). |
| 2. 후보 수집 | YouTube 서버가 걸러 주는 조건(기간, 지역, 언어, 카테고리 1개, 화질, 자막, 라이선스, 임베드, 정렬)만 search.list에 넣어 후보를 가져온다. 호출당 최대 50개, 기본 2쪽(100개), 최대 5쪽. 호출 1회 100 units로 가장 비싸다. |
| 3. 영상 상세 조회 | 후보의 영상 ID를 50개씩 묶어 videos.list로 조회한다(1 unit/호출). 24시간 이내 캐시가 있는 영상은 건너뛴다. |
| 4. 영상 필터 | API 호출 없이 서버에서 영상 단위 조건(길이, 조회수, 좋아요, 댓글, 비율, 태그, 키워드, 카테고리, 아동용, 지역 제한, 업로드 요일·시간대 등)을 적용해 후보를 줄인다. 비용 0. |
| 5. 채널 조회·필터 | 남은 영상의 채널 ID를 모아 channels.list로 조회하고(1 unit/50개) 구독자 수, 구독자 대비 조회수, 채널 영상 수, 개설일, 국가 조건을 적용한다. |
| 6. 채널 활동 조회 | 채널 업로드 빈도·최근 활동 조건이 있을 때만, 남은 채널마다 playlistItems.list(1 unit/채널)로 최근 업로드 날짜를 가져와 조건을 적용한다. 한 번에 최대 50개 채널까지. |
| 7. 계산·정렬·표시 | 파생 지표를 계산하고(‘계산값’ 표기) 사용자가 고른 기준으로 정렬해 20개씩 보여 준다. 단계별 남은 개수(후보 100 → 영상 필터 41 → 채널 필터 12)를 함께 보여 준다(srch-006). |
| 8. 저장 | 회원이면 검색 기록을 남기고, 조건을 프리셋으로 저장하거나 영상을 즐겨찾기(영상 ID만)할 수 있다. |
| 쿼터 설계 |  |
| API 비용 | search.list 100 / videos.list 1 / channels.list 1 / playlistItems.list 1 / videoCategories.list 1 (units, 호출 1회당). 목록의 id는 한 번에 최대 50개. |
| 검색 1회 비용 예시 | 후보 2쪽(100개), 채널 활동 조건 없음: 100×2 + 2 + 2 = 약 204 units → 하루 한도 기준 약 44회.<br>채널 활동 조건 있음(채널 50개): 약 254 units → 약 35회.<br>필터를 늘려도 서버 계산이라 비용이 늘지 않는다. 늘어나는 것은 후보 쪽수와 채널 활동 조회 수뿐이다. |
| 일일 상한 | 하루 10,000 units 중 9,000 units(소프트 상한)까지만 쓰고, 넘으면 새 API 호출을 막고 캐시된 결과만 보여 준다(quota-004). 남은 1,000 units는 카테고리 목록 갱신·즐겨찾기 표시용 예비. |
| 초기화 시각 | YouTube 할당량은 태평양 시간(PT) 자정에 초기화된다. 서비스는 PT 날짜 기준으로 사용량을 합산하고, 화면에는 한국 시간으로 초기화 시각을 안내한다. |
| 정책 준수 원칙 (YouTube API 서비스 개발자 정책) |  |
| 원칙 | 1. 공식 Data API v3만 쓴다. 스크래핑·비공식 API·영상 다운로드 금지.<br>2. 서비스가 계산한 값에는 ‘YouTube 제공 지표가 아님’을 표시한다.<br>3. 공개 통계 캐시는 30일을 넘기지 않는다(서비스는 28일 지나면 삭제, 통계는 24시간 지나면 갱신 대상).<br>4. 개인정보처리방침과 YouTube 이용약관 링크를 모든 화면에서 볼 수 있게 한다.<br>5. YouTube 콘텐츠임을 알 수 있게 출처를 표시하고, 검색 결과를 임의로 바꾸지 않는다(필터링한 결과임을 안내).<br>6. 회원 삭제 요청(탈퇴)은 즉시 처리해 개인 데이터를 지운다.<br>자세한 항목은 ‘정책 준수 체크’ 시트. 이 문서는 법률 자문이 아니며, 상용 서비스로 낼 때는 정책 전문을 다시 확인한다. |
| 유사 서비스 분석 (벤치마킹 초안) |  |
| YouTube 기본 검색 필터 | 업로드 날짜, 구분(동영상·채널 등), 길이(4분 미만·4~20분·20분 초과 3단계), 특징(자막·4K·HD 등), 정렬 기준 제공. 조회수·좋아요 범위, 구독자 수, 태그, 비율 조건은 없다. → 차별점: 세밀한 수치 범위와 계산 지표. |
| 채널 성장·분석 확장 프로그램 (vidIQ, TubeBuddy 등) | 키워드·태그 분석과 채널 성장 지원 중심의 도구로, 일부 기능은 유료인 것으로 알려져 있다. 영상 ‘검색 필터’ 자체가 목적은 아니다. (작성자가 직접 확인한 뒤 내용을 고칠 것) |
| 직접 확인할 것 | 비슷한 이름의 오픈소스/웹 서비스가 있는지 GitHub·구글에서 1~3개 더 찾아 장단점을 적는다(산출물 3번 ‘유사 서비스 분석·차별화’). |
| 알려진 한계 |  |
| 1 | 후보 풀 한계: search.list는 쿼리당 결과가 최대 약 500개이고 호출당 100 units라, 필터가 까다로우면 남는 영상이 적다. 화면에 ‘검색된 후보 안에서 걸러낸 결과’임을 안내한다. |
| 2 | 쇼츠 여부는 API가 주지 않아 길이(180초 이하)로 추정한다. |
| 3 | 싫어요 수, 시청 지속 시간, 자막 내용 검색은 공개 API로 얻을 수 없어 필터로 제공하지 않는다. |
| 4 | 구독자 수·좋아요 수를 숨긴 채널·영상은 해당 조건을 쓰면 결과에서 제외된다. |
| 5 | API 응답의 시각은 UTC이며, 서비스는 한국 시간(KST)으로 바꿔 요일·시간대를 판정한다. |
| 6 | 기본 쿼터만 쓰는 개인 프로젝트라 동시 사용자가 많아지면 하루 검색 가능 횟수가 금방 소진된다. 쿼터 증설은 YouTube의 규정 준수 심사가 필요해 범위 밖이다. |
| 7 | YouTube Data API v3 키가 없으면 서비스를 구동할 수 없다. 키를 발급하지 못해 실제 응답으로 검증하지 못했고(자동 테스트는 mock 어댑터 기반), 실제 응답 형식과 응답 시간은 확인하지 못했다. |
| 8 | 이용 횟수·요청 속도 제한 카운터는 서버 메모리에 저장한다. 재시작하면 초기화되고 서버를 여러 개 띄우면 공유되지 않는다. 쿼터 상한 차단의 동시성 보호도 단일 프로세스 기준이다. |
| 9 | 2순위 기능(‘2순위 기능’ 시트)은 구현하지 않았다. |
