2순위 기능 (tube-filter)

핵심 기능(1순위)을 모두 만든 뒤 구현한다. 1순위 문서에서는 빼고 여기에 모은다. 구현을 시작하면 해당 항목을 1순위 문서로 옮긴다(요구사항 ID는 ‘예정’ 표시를 떼고 그대로 쓴다).

| 번호 | 기능 | 요구사항 ID | 요구사항 | 2순위로 둔 이유 | 지금 지켜둘 것(전환 대비) | 관련 테이블 | 원래 위치 |
|---|---|---|---|---|---|---|---|
| 1.0 | 채널 지정 검색(키워드 없이) | srch-010(예정) | 채널 ID를 입력하면 그 채널의 영상만 필터링한다. | 채널 업로드 목록 조회와 필터 조합을 새로 설계해야 한다. 핵심은 키워드 검색 필터다. | 후보 수집을 ‘후보 공급자’ 인터페이스로 만들어 search.list 외에 playlistItems도 꽂을 수 있게 한다. | - | 요구 명세서 srch-001 비고 |
| 2.0 | Google 로그인(OAuth) | auth-006(예정) | Google 계정으로 로그인한다. | 공개 데이터만 쓰므로 OAuth가 필요 없고, 범위 요청·검수가 생긴다. | 회원 테이블의 login_id/password 외에 외부 계정 식별자 칼럼을 붙이기 쉽게 둔다. | app_user | 요구 명세서 auth-001 |
| 3.0 | 정규식 제목·설명 필터 | flt-017(예정) | 제목·설명을 정규식으로 검사한다. | 정규식 서비스 거부(ReDoS) 위험이 있어 길이·시간 제한 설계가 필요하다. | 단어 필터를 ‘문자열 매처’ 인터페이스로 만들어 두면 정규식 매처를 추가하기 쉽다. | - | flt-012 |
| 4.0 | 저장 필터 새 영상 알림 | alert-001(예정) | 프리셋 조건에 맞는 새 영상이 올라오면 알려 준다. | 정기 조회가 쿼터를 계속 쓴다. 하루 한도에서 사용자 검색과 경쟁한다. | 프리셋 조건 형식을 검색 조건과 같게 유지한다. | filter_preset | pres-001 |
| 5.0 | 채널 비교 대시보드 | chan-003(예정) | 채널 2~5개를 골라 구독자, 업로드 빈도, 평균 조회수를 나란히 비교한다. | 채널 상세의 확장이며 핵심 흐름과 무관하다. | 채널 상세 API를 채널 ID 목록 단위 조회로 쓸 수 있게 둔다. | channel_cache | chan-001 |
| 6.0 | 키워드 추이 분석(장기 저장) | - | 키워드별 조회수·업로드 수의 장기 추이를 보여 준다. | YouTube 정책이 공개 통계를 30일 넘게 저장하는 것을 막아 설계상 충돌한다. 정책 확인 전까지 보류. | 캐시 보관 기간 상수를 한 곳에 둔다(CACHE_MAX_DAYS). | - | 정책 준수 체크 3번 |
| 7.0 | 로그인 시도 제한 | sec-007(예정) | 같은 IP에서 연속으로 로그인에 실패하면 일정 시간 막는다. | 로컬·포트폴리오 환경에서는 위험이 낮다. | 로그인 실패 처리를 한 곳에 모은다. | (login_lock) | auth-002 |
| 8.0 | Docker 배포·HTTPS | - | Docker 이미지로 묶어 외부에 공개하고 HTTPS를 적용한다. | 기능과 무관한 인프라 작업이다. | 설정은 모두 환경변수로 받고, 세션 쿠키 Secure 옵션을 환경변수로 켤 수 있게 한다. | - | 설정·규약 세션 |
| 9.0 | 쿼터 증설 심사 | - | YouTube API 규정 준수 심사를 받아 할당량을 늘린다. | 상용 서비스 단계의 일이다. 포트폴리오는 기본 쿼터로 설계한다. | 쿼터 상수를 환경변수로 받는다. | - | 프로젝트 개요 쿼터 설계 |
| 10.0 | 다국어 화면 | - | 화면 언어를 한국어/영어로 바꾼다. | 핵심 기능과 무관하다. | 화면 문구를 템플릿에 직접 쓰되 오류 메시지는 코드값(code)으로 구분해 둔다. | - | - |
